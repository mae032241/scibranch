# 当前架构：薄 H/W/A/E 控制层

简体中文 | [English](ARCHITECTURE.md)

控制层默认不计算科学数据或输出哈希。哈希仅限审批绑定、确实需要持久幂等的小型控制请求，
以及宿主拥有的 Git 代码捕获。声明工程基础采用普通 Git 工作树检查，控制层不逐个读取
或 hash 基础文件。
审批/幂等入口不得遍历科学文件、代码、日志、观察、输入、
结果、Skill 或归档内容。显式科学工具
可以按自己的算法处理选定证据，这不属于控制身份计算。协议 28 使用
`record_ref = {"path": "/absolute/original"}` 与
`file_ref = {"path": "/absolute/original", "size_bytes": N}`，控制绑定采用 `*_ref` 字段，
以路径、producer 和生命周期身份取代内容摘要。旧留存对象采用 UUID 路径，不按内容去重，
也不保留哈希缓存。fork manifest v2 沿用此引用合同。独立归档与整实例 cold checkpoint 包
已退役。仅支持协议 28、worker/lineage view 1、soft 预算及最终 A 策略 v1 的当前实例；
旧格式明确拒绝，不提供兼容读取、迁移、恢复或 owner 重新激活。
一次性工程救援命令、历史执行豁免及旧用量回执的派生修正已退役；依赖这些救援记录的实例不再受支持。当前同 session 增量计量、普通重启恢复和增额后的续接继续支持。
Linux 只读挂载保护科学命名空间中的
选定输入；可信同 UID 进程仍是软边界，不承诺防止主动改写或检测内容篡改。

新实例由 `scid-research` 管理，实验工具为 `scid-experiment`。没有 LLM Root、MCP 调度服务或后台 Root daemon。
核心提供薄 CLI 与实例 UI；旧 CLI/MCP/UI、Root 宿主、平台配置生成与 legacy systemd 部署已退役。

`research_config.py` 是 TOML、CLI 与宿主入口共同的准备、默认值和校验路径。新实例冻结实际生效设置；修改新建声明不更新已有实例。`backends.py` 将 Codex 与显式 protocol 输运隔开，不接管科学判断、预算或执行授权。protocol 权限为 launcher 提示，不证明隔离；不支持原生续接和完整作者证明，不能取得正式独审。开启子 Agent 也不证明作者或用量完整。具体字段与限制见[配置与后端参考](RESEARCH_CONFIGURATION.md)。

普通科学回答只必填 summary、scientific_result、limitations，H/A 另填 next_action、
route_reason，W 另填 stage_intent。标准 Codex 以简短提示要求 JSON，本地核必填字段和
实际消费的控制选择；其余科学内容开放，不套可选字段嵌套 Schema。正式独审保持独立的
严格合同。已冻结 Schema 原件不改写；普通任务即使保留旧严格 Schema，出站也使用当前
最小回答说明，protocol 携带当前最小 Schema 投影。已记录的工作开始前格式拒绝保留
原调用的有限恢复路径。实际传输方式与能力声明分别记录，自定义 launcher 权限沿原合同。
H 的 minimal_test 接受非空文本、对象或列表；结构化说明只在控制投影显示为 JSON 文本，科学原件不变。错误诊断定位准确条目和字段，合法焦点不需修改。

回归检查将新默认普通角色最终回答的固定合同限制在 3 KiB，覆盖 Codex/protocol 的普通、续接、
补填和 W 片段实际分支，计入 512 字节补填诊断余量。科学原件、动态准确引用、预算和用户
指导完整保留并另列大小，不靠截断这些输入达标。保留的旧冻结科学指导及历史任务输入同样
另列，其实际总量可能超过新默认上限。正式独审与 Local 执行结果文件属于独立合同。

`configuration_updates.py` 将运行配置修订与原始设置身份分开保存。新节点构建输入前绑定精确版本；已有节点及其原调用在校验、执行和恢复时沿用各自配置。保存只排队，不启动研究。配置变化保留累计预算与资源账本、未决执行事实和 FINAL 边界。可编辑字段及已生效、待生效状态见配置参考。

冻结的权限摘要分别记录请求值、实际策略、实施方式与限制；标准 Codex danger-full-access 不强制离线，read-only 不因网络请求启用联网，protocol/自定义 launcher 仅作权限提示，实际访问未知。

CLI 是应用核心，网页复用相同公共控制和读取逻辑。`control_operations.py` 持久记录 detached 推进及科学预算修订；独立控制进程使用原写锁，不依赖网页进程常驻。暂停阻止下一节点，已接受工作按原限制完成。预算修订在安全边界应用，不重置消费或未知用量；unknown 原调用须核对，不自动重发。

`user_guidance.py` 将全局/角色建议绑定到下一匹配新任务或后续研究。待应用项可按 revision 修改/撤销，已应用任务输入不可改写，后续研究撤销另留未来生效回执。建议可不采纳；显式目标变更保留原目标记录，并声明生效节点，不授执行权限或科学资格。

## 责任与数据流

```text
操作者的目标、输入、配置、有限预算
  -> CLI prepare：冻结实例设置
  -> controller：原实例写锁、预算、暂停、角色路由
  -> native：独立 H / W / A / E 原生线程
  -> 科学 JSON 与精确成果封存
  -> A 的科学去向 -> controller

W -> scid-experiment -> 冻结执行接口 -> local / 领域 adapter
                              -> 原调用 query / cancel / collect
CLI serve-ui -> 同一实例的只读视图与控制命令
CLI 原调用恢复 -> 同一调用核对与有限维护
```

H 负责机制与假设；W 负责有界实验设计、实现与观察；A 负责贡献、证据缺口、后继方向和交付选择；E 负责所请求的证据工作。
控制层拥有身份、冻结绑定、预算、资格、权限和机械发布，不制造科学结论，也不在提示词中
给 Worker 增加哈希计算、比对、校验或哈希清单工作。Worker 写普通科学文件；控制程序
按上述引用合同，在宿主私有空间记录精确路径、producer 和声明大小。

私有任务和转交记录保存已有生产者产物清单的引用及所选 ID，不逐节点重复文件描述。
操作入口只加载本次所选清单一次，将事实传给消费者；普通控制记录读取不隐式加载材料或遍历历史。
每份产物只记录一个原始来源路径。受管调用的 `experiments/<call_id>/` 发布目录由控制层独占；
W 直接引用受管原件，把新报告放在该目录之外。作者打包占用此目录时交回修正交付，
保留原调用及结果，不重跑实验。W 的 null 只保留已有明确选择，不表示转交全部输入。
公开进度使用已接受节点身份，不依赖任务正文大小；探索投入 UI 使用生产者的摘要版本。
候选下载保留准确封存编号及已保存的调用输出绑定，支持原地留存原件。
FINAL 的提交和确认仍是两个动作，只有当前 FINAL 的确认成功才标记交付完成。

本地结果指标仍须有不同的非空名称和明确有限数值。`unit`、`evaluation_key`、`direction`
与标签是可选科学说明，不强制优化方向枚举或科学文本长度。显式候选须绑定唯一已声明且保留
的精确成果；指标缺失或无法关联时保持 unknown，不改选其他指标或推断方向。坏指标、成果声明
或无法存入严格 JSON 的说明按字段或条目诊断，保留其他有效结果和有精确成果绑定的候选身份。`result.json`
原始字节不改写；紧凑预览与被省略字段的诊断链接该留存原件。

启用 H search 承诺时，`prepare --candidate-extra-slots N` 冻结可选提名预览的额外数量建议，默认 2。
W 可在 `candidate_nominations` 声明机制代表、额外备选或缺口，但不要求逐机制重抄表格。
代表项为 mechanism_ref、candidate、reason，额外项为 candidate、reason，缺口项为
mechanism_ref、reason。当前调用候选可用 `{call_id, artifact}`，历史候选沿用科学引用。
预览仅解析可识别条目及候选身份；省略或无法解析提名不触发输出补填，也不限制完整候选池。
无法解析的非空提名保留非阻断诊断及原结论位置，任务和网页可见；紧凑视图保留计数与完整索引入口。控制不据标签推断候选，也不自动读取声明中的文件路径。
跨机制 observed finding 使用作者声明的准确 call_id，同一比较调用可支持多个机制，不需要新实验。
机制归属、优劣与缺口由科学作者判断；最终机制覆盖另由 A 的 final_coverage 承担。

最近封存 W 的分类提名构成默认比较预览，独立分页保留完整提名、理由及原结论入口。
原候选池、实验和精确材料沿用完整分页及交付目录，池的数量不受提名名额限制。
A 可按需读取并推荐池内任一模型，在科学正文解释理由，不改写封存 W 提名，
也不需要为调入已有模型重新实验或登记。无 H search 承诺的任务不制造机制覆盖。

科学机制及处置列表没有固定四项或 128 个机制容量。已配置的初始调用机会、精确额外授权、
已接受调用消费、有限执行预算及未知原调用核对仍约束执行。分页索引保留全部机制和原科学文本，
默认导航视图继续有界。

`screened` 表示 A 已评价精确 W 证据，不排除以后继续深挖；`deferred` 暂缓并保留未决路线；
`waived` 才是 A 的明确科学排除。A 须针对原目标与约束，用证据支持每个排除的否定或不可行
理由；暂时相对落后或缺证据应说明暂缓，不能直接视为科学否定。H 先比较可信的竞争机制再
说明集中理由，单机制范围也由 H 解释；参数试验次数本身不证明不同机制均有判别证据。
控制不裁判理由的科学充分性。

普通 A 检查代理、验证和审计证据是否回答原目标，包括条件变化导致排名反转和同族反复微调。
当前机制遗漏与目标相关的假设，或遇到科学瓶颈时，即使现有方法仍在改进，也应选择
`revise_h`，把缺口、留存证据和待决问题交给 H。H 据此修订、重开或新增具有不同关键假设
或失败方式的机制及判别测试，在初筛后继续重看可行备选。H 范围足够时，有界的方法、改进
和实现故障修复仍经 `continue_w` 交 W。缺失输入保持缺失；证据也可支持集中、暂缓或有限
收口。这些是科学指导，不新增响应字段、配额或准入门槛。自定义及已准备的角色原文保持冻结；
当前 launcher 工作规划不在 protected FINAL、
closeout 或输出补填期间授权新工作。
角色指导、A 的通用证据判断、普通阶段规划和响应字段语法各自承载不同规则；文件、JSON 和
本地分析的通用读取方法沿用任务已有的 `reading_order`，不在阶段规划重复。Codex developer
指令与协议 prompt 是两种替代传输方式；角色原文只通过选定方式发送一次。

机制索引提供已采纳 A 处置理由的有界预览，并链接完整科学 JSON 原件；原件不受导航页大小
上限省略。同状态重述或遗漏不替换原理由与来源；H 修订会清除当前处置，历史原件仍保留。
所有启用 search 的实例默认向 H/A 展示完整组合：实际已接受调用数、剩余初始/额外机会、
已完成独立 W→A 投入及未服务完整周期。调用数和周期数是活动事实，不是科学覆盖、价值排序
或每机制资源成本。稳定身份顺序只作导航；局部 improve/repair/validate 不抹去全局视野，
科学说明和 H 修订也不清零投入。所有未 waived 路线（包括 screened）进入未服务周期观察。
`search_policy.initial_calls` 配置初始受管调用机会；显式组合周期控制额外提醒。
每个实质评估已完成 W 的 A 提交紧凑 portfolio_review：
main_line（准确机制引用或 null）、reason（一段自由科学说明）、discriminating_work
（null 或三键新工作声明）。说明比较最强可行竞争解释、
最低成本判别工作、本轮动作，以及暂缓触发和再议条件；无可行替代时说明理由。
要实施或暂缓的新工作必须显式声明；无可行新工作用 null 并在 reason 说明。
缺少必需内容走同任务有限输出补填。等待、无完成 W、明确无 search、正式独审豁免；
FINAL 实际评估已完成 W 时适用同一判断。

pending 处置幂等恢复未完成工作，不清零消费。已声明 discriminating_work 保留准确 A 来源
与后继响应；新工作只填 mechanism_refs、question、next_action，work_updates 可选且稀疏，
已填写项使用 work_ref、action（execute/defer/withdraw）、reason；遗漏保留原状态，显式 execute
仍须匹配实际路线和 focus。相关条件和证据合入理由，
其余科学细节可选；执行不自动解决科学问题。当前主线与下一判别实验可指向不同机制，
真正 focus 和执行权限仍显式检查。

投入按独立 W→A 完整评估周期去重，待 A 的 W 单列。portfolio 索引持续保留真实参与、
未服务周期、A 明确主线的连续次数和活跃判别待办。同周期可涉及多个机制，比例合计可超过
100%；恢复和补填不增加周期，fork 仅取准确 cut。按 token 参考轮数须有足够完整报告样本
及已知余额；usage 缺失或滞后保持不可估。这些事实不授资源、不强制轮换，也不判科学价值。

结束或 FINAL 的 final_coverage 对每个冻结机制仅填 mechanism_ref、status（deep、
screened_pending、ruled_out、unexplored）、reason。理由说明证据和未答问题，
limitations 保留输入与资源缺口。finish/deliver 和 protected FINAL 使用同一门槛，
不授权新实验，也不从候选存在或调用成功推断科学深度。

广度预算判断读取普通工作可用量与运行时 `work/budget-status.json`。当前 protected FINAL
只按 provider 已报告消费计算 token 余额，未知账单保持未知，不估算收费或扣旧收口预留；
真实执行未知仍须按原调用核对。旧预算内收口格式不受支持。调用机会不预留实际资源，也不保证覆盖；昂贵调用应使用已有执行配置
和 W 阶段目标约束，不引入自动广度比例、最低机制数或新的执行权限。

H 只声明需要变更的 commitment；遗漏保留原承诺及已采纳 A 理由。repair 按稳定机制 ref
绑定唯一精确直接 W 观测，或通过既有 `implementation_selection` 选定的原 accepted 输入。
多个可能观测须精确选定；相同输出字节、label 或最近对象不提供来源身份。共享归档路径
不能证明逻辑输入身份，此类输出不能用于 repair 来源消歧。旧 W、call、accepted
及终态原件仍按自己的旧 H seal 校验，当前 H/A 的新授权另行冻结。进程已知成功不排除科学上
需要修复；unknown、原件缺失或改变、来源模糊及修复次数耗尽仍阻断，并在作者控制回执中提前
诊断。旧 screening 资格不继承，机会及总消费不退款。H 科学范围未变时，A 可用 `continue_w`
加显式局部 focus 请求审查后的下一有限 W stage；原 stage 消费继续累计。修订 H 用于科学承诺
改变，不能重置预算。
初始/额外机会保护首轮筛查，不是后续实验总次数上限。运行预算和执行权限来自操作者配置与控制账本。H 规划科学问题和机制，A 评估证据并在该范围内决定去向，W 根据控制层提供的额度规划自己的工作。H/A 的资源估算及建议调用、审计次数，不成为运行上限，也不因用完这些建议次数就要求重开 H。科学实验设计中的数量、用户与任务要求、真实单次执行限制仍保留原义。

普通 W 提示采用增量实现与验证，根据证据和当前预算安排下一步。原工具会话仍在执行时，通常在实际截止时间内有限等待 10–30 秒；这是建议，不是新的轮询策略。最终回答、交回宿主等待和核对仍服从真实 handoff。补正、受保护 FINAL 和作者收尾保持原有边界。

一次受管比较可通过既有 `mechanism_findings[].call_id` 支撑多个作者声明的观测，科学筛查仍由 A 判断。
调用身份、机制授权绑定和消费只记一次；已有工作仅缺引用时补正输出，不另开执行登记。
初始机会保护尚未完成的 pending 机制；A 已评为 screened 的机制不必为耗掉机会单独执行。
此口径使用 accepted 广度摘要版本 2，旧摘要明确拒绝，不回放、迁移或重标版本。

需要交接的报告和诊断脚本放入 `artifacts/`，`work/` 仅为临时材料。普通 A/H 沿既有输入绑定转交
当前材料引用，准确的 E 请求往返与 selected fork 同样保留该集合。null 保留、`[]` 清空、明确 ID
替换；已接受的空集合不从较老父节点重新补回。新 W 输出刷新自动转交集合，W 通过既有选择字段
明确保留后续仍需复用的旧实现。仅转交引用，不复制模型或祖先工作目录，原输入配额仍有效。

解码后的 `text` 可精确还原全文，末页不含 `next`。短字符串保留原形状。这些限制只针对
省略部分，不针对整个证据索引；文本详情入口也不等于被省略原件的读取入口。

## 不可退化的边界

- 科学作者负责比较和选择候选。控制按首次观察顺序保留全部候选，包括同分和缺少指标者。
  紧凑预览只作机械省略并链接完整原件，不裁剪交付目录。选择策略版本 2 精确为
  `{"version":2}`，目录不启动领域调用。A 交付须明确命名目录成员，在 `scientific_result`
  说明选择依据。`candidate_comparison` 是可选科学说明，其行、`keep`、理由和证据步骤格式
  不授予或阻挡交付；真实 audit/deliver 仍要求精确可用候选、资格与执行权限。
  null 不授权交付。协议 28 拒绝旧冻结协议，不迁移或改写其原件。
- 一个实例只有一个推进写者；只读页面不调模型，不重建第二份预算或科研状态。
- 科学原文、成果、配置和原调用均按精确身份冻结；修订不能继承旧对象的批准或资格。
- 来源未知保持 unknown；正式独审排除精确对象的全部已知作者与参与者，普通 A 不自动成为正式审查。
- 科学判断、正式资格与执行批准分别解释；聊天或手写决定文件不构成人工批准。
- 未知外部提交只核对原调用，不退款、不重发；恢复不重置额度、不生成另一个 owner。
- UI 转义作者内容；附件按精确封存成员读取，HTML/SVG 仍下载，不执行。
- 当前信任 Worker 及宿主同权限进程，属于软控制边界，不主张防恶意进程隔离。

授权读取只核对不可变声明、身份、精确对象、范围及已声明的期限或撤销状态，不遍历执行结果或重放科学结论。
真实效果入口显式检查科学资格与原件完整性，并独立检查当前预算、暂停、活动或未知执行的准入条件。
结果损坏或缺失不抹去已接受意图和消费，也不妨碍查看或撤销授权；它会阻止新效果，或使相关终态和计量事实保持未核实。
已接受调用的 collect/cancel 保留原权限与调用身份，不变成新的提交授权，也不重发原调用，仍受原调用或显式有限维护窗口约束。

普通 A 任务要求逐项对照原目标和授权范围，以可定位观察及实验条件支撑关键主张，区分
测量、推断和假设、目标指标与代理及敏感性检查。A 按同一目标准则比较相关候选，说明
冲突证据、不确定性和缺失输入。流程结束、审计资格、预算耗尽、`finish` 和交付均不证明
未测量的目标已经完成；停止时 A 须报告未满足的目标。

普通阶段规划建议作者沿现有输入选择保留公开比较方案，以及评价脚本、报告和完整流程的准确引用。
条件变化会限制比较；流程级证据不能静默转给另一个保存的产物。普通研究收口前，A 可请求一次
小规模、可负担的完整流程比较，使用共同条件及有价值的重复测量。这些建议不新增配额、按分数
默认选择或完整性门槛。FINAL 只使用既有证据；作者可拒绝全部候选，或保留缺失比较并有限收口。

H 基于 A 的证据、限制和准确引用决定机制变化与下一项最小判别，只针对具体矛盾核查，
避免默认重做 A 的全池评估。A 独立复核能改变路由或选择的疑点，可按需要扩大或有界复现原件；
新候选开发、调参研究和大规模重测交 W。作者通过现有声明输出发布可复用诊断，以及实际执行
版本的自有源码和必要 helper，遵守任务代码路径与工程写权限。受管原件直接引用。未发布的
诊断如实保留为缺口，不新增材料非空要求或补正门槛。

A 在普通科学正文解释候选准则、修订、证据及代价，selection_explanation 可选，
不再有独立嵌套完整性门槛。精确候选身份、冻结输入、审计资格和交付授权仍须核对。
必填内容、无法消费的作者动作引用及明确诊断的交付布局冲突，沿同一任务有界补正，
封存与修复入口共用消费校验，保留累计消费与 FINAL 完成保护。
原作者可删除冗余副本或分开自己的冲突文件，受管原件保持不变。受管输出持续保留、可直接
引用，无需另复制到作者 artifacts。原件身份、IO、执行未知及授权问题仍由控制层处理，
不据此自动拉起作者重试。

Local 不消费的候选 parent/change 说明不阻断，也不建立父模型关系；真正消费父模型的执行器
仍检查准确引用。重复 argv 数量和字节门槛移除，保留实际消息传输边界及字符串/NUL 要求。
明确的 caller_error、accepted=false 把具体参数或输入错误交回作者。若原 W 因该末次 run/compile
拒绝而结束且工作未完成，控制层可按原自动接续权限在同 task/session 有界重开，覆盖 improve 和
无 search 的普通工作；同 turn 已有后续接受结果时不再补正。这种准确机械拒绝在原有限额度内
优先于该返回的 decision/blocked；没有这种拒绝时，真实科学 decision/blocked 仍交 A，
已接受未知调用仍只核对原调用。已接受调用的某次操作失败不抹去已核验原终态；除原件完整性
错误外，明确发生在该操作开始前的失败报告不可用，包括本地加载或资源检查，审查要求保留
自身状态。实际提交后失联仍按原 ID 保留 unknown。后端异常原文只留宿主诊断，公开回执
保留安全的操作和错误类别，Worker 客户端保留宿主 handoff。未知命令的原参数交作者自行修正。
FINAL 与 closeout 复用同一 native collector，处理 interrupted 和已接受但尚未启动的 attempt。
只有宿主明确的提交前预算拒绝可据此转 FINAL，完整原 attempt 链和累计消费保留。

科学最终输出的解析容忍一次起始 BOM，以及包住整段单个对象的普通或 json Markdown 围栏。
前后散文、多个对象和错误 JSON 仍走有界补正。原始字节不改；封存、历史读取和显示共用
科学解析器。只有实际规范化时才在 native outcome 记 scientific_output_normalization，
控制 JSON 继续使用严格读取。
父节点的 `inputs/parents/<step>/conclusion.json` 可能直接引用带 BOM 或围栏的原始作者文本。
脚本读取它时须使用相同的窄科学解析规则，不能假定 `json.load` 可直接解析。

`native_recovery.py` 分类原生结构化失败字段及窄匹配的原生失败信封，通过既有 continuation/controller 路径给出唯一
有界恢复决定。中途的顶层 `error` 诊断不否决后续明确的原生成功终态：唯一完成事件、零退出码和已确认清理可解除此前诊断。真正失败、中断或未完成的 turn、完成后的错误或活动、重复完成及缺少终态证据仍沿用原失败处理。收集、补正准入、历史校验和用量覆盖使用同一终态解释。留存 pending 输出与原最终消息字节、终态计数一致时，普通收集入口可封存同一调用，不新增模型回合；原 outcome、pending、usage 和 attempt 身份保留。

尝试、分别计数、服务等待及限制，服务等待不冒充科学失败，也不建立第二份状态账本。
本批不新增必填科学输出、不提升协议，也不替换通用科学预算时钟。

H 选择 `wait` 且没有 pending 或未知外部执行时，进入既有持久 FINAL；存在原未决调用则保留等待机制。此入口要求已冻结的最终 A 完成能力，缺少时如实返回 `final_unavailable`，不补造完成授权。普通 A 明确 `finish` 即结束本轮且零提交；未配置交付策略时，`deliver` 与 `finish` 使用相同停止行为，原封存科学选择保持不变；已配置时，`deliver` 只消费原封存 A 的精确候选授权，不强制新 FINAL A。启用选择策略时，普通 A 原任务先冻结并展示完整比较目录，交付仍核对同一目录、原件及资格；失败或缺资格保留未决结果，不自动改选或新起科学作者。共享预算阻断保留原路线；可选 H/A 节点准入拒绝改为返回 H 作有界控制澄清，沿现有 author-correction 绑定准确封存选择及实际拒绝原因。首个根和原因跨重试/预算修订保持，既有两次补正额度不重置；下一科学选择仍核当前角色份额、无证据重复、共享预算和执行门槛。H 选择 W 才重新进入正常路线，控制不虚构实验或新证据；原调用活跃或未知时不启动这次 H 澄清。局部 W 只提名本次冻结范围内机制；按机制的最近声明及各自来源供 A/FINAL 读取，其他机制既有代表和缺口保持，新机制显示 pending，screen 仍可全局。

普通控制收口分别保留以下边界：

| 封存选择或控制事实 | 后续边界 |
| --- | --- |
| H `wait`，无 pending/未知执行 | 持久 FINAL；缺冻结完成能力则 `final_unavailable`。 |
| H `wait`，存在 pending/未知执行 | 保留等待及同一原调用。 |
| 普通 A `wait` | 停在原封存 wait；只有准确显式 continuation 才可续接。 |
| 普通 A `finish` | 停止、零提交，不断言整体目标成功。 |
| 普通 A `deliver`，无交付策略 | 按 `finish` 停止，科学路线 `deliver` 保持。 |
| 普通 A `deliver`，有交付策略 | 仅消费原作者的准确授权；交付失败保留科学结果，不补新作者。 |
| 已知完成但输出需修复 | 仅使用原冻结有限修复权限；耗尽返回 `output_repair_unavailable`。 |
| 科学澄清额度耗尽 | 返回 `semantic_correction_required`，保留首根及已耗次数。 |
| 可选 H/A 准入被拒 | 沿同一补正额度返回 H 有界重选，仍核当前准入。 |
| 共享预算不能启动新动作 | 进入既有 FINAL；适用时保留准确待执行路线。 |
| 已核验外部终态，但唤醒时间额度耗尽 | 保留终态证据，返回 `managed_execution_terminal_wake_deadline`，不绕过唤醒准入；仍 pending 的截止继续为 `managed_execution_wait_deadline`。 |
| 实际执行或清理未知 | 保留原未决边界，不重放、不补作者、不虚构清理。 |

预算修订后重建历史时，已准入的普通后继保持准确科学路线；当前角色份额只约束新准入，包括已准备但尚无 native acceptance 的后继。

新 `prepare` 冻结 `final_a_completion_policy` version 1。普通状态检查剩余共享额度能否启动下一动作；该模式不为 protected FINAL 预扣共享 token、时间或步数，也不在启动时预付整个节点 token 目标。已报告 token 余额为正即通过普通 token 启动检查，仍须满足原有限时间、步数、完整性与执行门槛。H/W/A/E 单节点 token 目标统一为 soft，达线提示收口，不仅因达线拒绝新受管实验或强制转 A，原节点可以完成原结果；author closeout 的 token permit 同样为软目标，有限时间仍强制执行。协议 28 仅接受 soft 节点设置及最终 A 策略 v1；旧协议、hard 设置和缺少最终策略的旧格式均明确拒绝，不迁移。不能启动便在现有控制账本进入持久 FINAL。每个 FINAL 周期通过 `final_a_return` 只接受一个精确原始 A，基于已有已接受 W 给结论、明确选择，并说明未满足目标与缺失输入。共享 token、总时间或步数预算不足、为零或超额均不否决这次 A；有原件与交付权限时由 host 执行其原授权提交和同操作确认，输出真实结果。缺少 W、原件、权限或未核对原执行时明确未提交，不制造科学结果。未配置可选节点预算时，原冻结全局 token/时间设置提供最终调用的参考目标与有限单次时长。

provider 已报告实际用量、cached input、时间及步数全部保留；未知账单继续标注未知，不估算扣费，原上限不改、不退款；`final_overrun` 单列 token 超额。同一 FINAL 周期不派发新的 W/E、独立科学审查、纠正节点或另一轮 A，原 host 提交内必要机械资格检查仍保留。
冻结的 output-repair 策略仅可续接同一最终 A 任务补全输出，保留原授权、累计用量、
有限次数及原调用时长；它不授权重试未知执行。

这次精确最终 A 的原生完成与账单覆盖分别判断。原 `turn.completed` 事件、退出码 0、
原进程组已确认清理及科学输出完整时，即使用量缺失或无法与实时计数对齐，仍可封存。
已观测下界和未知账单分别保留，不补造零用量或完整计费覆盖。仅计费未知也不阻挡该 A
明确授权的原 submit 和同操作 confirm；缺少完成事件、非零退出、清理未知或外部效果
未核对仍保持原未决边界，不授权替代 A 或重放。

用户之后明确提高阈值且足以启动原待执行 normal 动作时，下一次 run 从 FINAL 前保存的逻辑路由恢复。`budget-amend` 本身只记账，不启动模型。恢复使用单调递增的新物理编号，所有旧最终 A、交付与消费不变；运行中的原最终 A 先收集，未知外部效果须按原调用核对。最新修订降低阈值或提高后仍不足，不恢复、不重复 A；以后再次预算不足进入新周期，各周期一个最终 A。主动 closeout 没有待恢复路由时保持终态。缺少当前必需冻结策略的实例明确拒绝。

后续只可使用原决策的有限 `submit` 和同操作 `confirm`。即使共享总时间已经超出，
原 A 单次调用、清理和每次交付动作仍保留已配置的有限时间上限。
资格、授权、精确原件核对、RSS 和取消仍有效。未知外部提交只核对原调用，绝不重新提交。
原生执行没有逐 request 准入 hook；此策略不保证进程、清理或传输故障后仍能产出报告或提交成功。

## 声明来源与审查

资格消费精确冻结原件，不按名字、相同字节或最近对象猜测来源。受管执行可通过
冻结能力声明输入来源；自包含 TCAD V2 package 必须匹配准备归档和原 reviewed
producer，编译 V3 输入保持原 compiler 链。明确不完整的声明不能回退为更广的来源主张。
可选 observer 须另行启用冻结来源合同，并提供绑定精确 observation 的来源视图；
请求描述当前观察，不传完整的历史 candidate/context 列表。返回的候选和 parent 引用
通过冻结 prefix 定点选择旧事实；一次操作复用同一 producer 的事实及相邻留存元数据，
不遍历此前节点。独立历史投影同样按冻结 prefix 核对实际推荐的候选。
可变观察元数据按现有存储策略保留采集时版本；模型仅复用准确的受管输出原件，缺少留存归属的 live 路径明确不可用，不复制模型或伪称归档。后续提交替换标记不改变前次已采集事实。
展示 coverage 本身不授予资格。真实 producer 贡献即使未被选为 implementation 也进入
作者集合；普通 parent 链不自动生成作者关系。

普通探索不要求固定的正式审查阶段。所请求的审查须绑定精确对象与经核验的贡献者；
普通 A 解释不构成独立审查。来源限制沿冻结输入传播，未知来源保持 unknown。
这些核验仅覆盖框架声明范围，不证明任意 native 外读封闭或科学正确。

## 历史任务分支

`fork_service.py` 为 CLI 与 UI 提供共同的预览和创建路径。父实例须冻结协议 28、严格静止，
并保留所选精确逻辑任务 N、原输入 cut 和必要控制记录；不要求最近 A 已返回 `finish` 或整个
研究已完成。不支持的协议、缺失 cut、歧义或损坏的控制身份均明确拒绝。未知 native、受管
执行、准备或交付效果须先按原调用对账；分支不自动重提。科学原件由实际依赖它的消费入口校验。

新分支拥有新实例身份，首任务保留逻辑编号 N，在新 native session 中从 N 的冻结首次科学输入
重跑。N 的输出、后续任务、工具反馈及 continuation/repair attempt 上下文不作为该任务输入继承。
入口只选逻辑任务，不提供任意 attempt 断点或 remaining-at-cut 预算模式。普通任务保留所选路由；
FINAL 与 closeout 任务保留阶段和来源 cutoff，新预算本身不把它们改为普通探索。正式审查保留
中立的精确 subject 合同与独立性门槛；工程修复保留有界 repair 合同。有 continuation 或输出修复
的任务也从首次输入重跑，不续接这些 attempt。

`fork_sources.py` 只收集所选任务的必要 typed 控制、准确引用的代码版本与当前草稿，不对
父实例全目录作 inventory 或完整保留。已选 run 的原七字段 `code_version` 绑定有界的
commit/tree/blob 对象，传入子实例自有私有 Git；不依赖父仓库 alternates、对象硬链接或
持久交接 bundle。父私有 Git 删除后，已经转移的代码版本仍由 child 持有。

当前 dirty/untracked 代码 B 与历史代码 A 分别传递；构建所选 child job 时，B 复制到既有
可写 `code/`；声明工程时，只恢复 `project/` 下准确声明的 editable 草稿，基础工程仍为原
共享外部依赖。未封存交接草稿保留在现有 `visibility=private_snapshot` 条目中，作为可读的
惰性私有状态，不写入 child 的 native 执行命名空间，不生成 native intent、commit、seal、
科学资格或执行许可。科学可见范围仍由原任务准确输入 cut 限定。

必要 job、seal、accepted、compiler、authority、history 与 recovery 控制复制到 child 的
既有私有存储；原逻辑身份保持，继承读取器使用这些声明的副本，不要求父 jobs/control 中
已复制的文件继续存在。`originals.py` 沿声明的 origin、路径、大小及已保存指纹，在实际消费
时解析并核对科学原件。科学数据、global/declaration 输入及节点产物直接引用其实际原件；
fork 不复制或硬链接其正文，不新建源冻结缓存，也不打包输入。原件删除后，对应消费可以
不可用；manifest 与所选任务元数据检查不重开未选科学正文。发布与恢复仍核对原事务及
inode，不重试外部执行。

native home、认证、模型 session、工具、solver、许可证及执行环境不复制。
冻结的模型、权限和 launcher 声明仍只是声明；任意未冻结 native 外读不保证可移植。声明的外部
runtime/adapter 读取范围、命名空间映射和交付目标保持冻结；分支不复制、重建或扩大它们，
子实例继续时仍须合法可用。当前闭包上限为 65,536 项、复制控制/草稿 4 GiB、16 层祖先，
每份需解析的控制 JSON 上限为 32 MiB；科学 locator 不按其正文大小计入复制量，已选代码
另守上述有界 Git 规则。

操作者须声明正的有限新 token、活动时间及控制动作上限。子实例记账衡量新工作，逻辑编号 N
不等于新消费 N 次动作；继承的科学投入与比较机会仍进入科学历史。历史成本单列：计量不完整
则保持 unknown 并保留已知下界，历史活动时间及全部控制动作不伪称精确重建。新额度不清零
历史科学投入，也不把缺失用量变成零。来源限制随精确原件传播；历史审查 verdict 和执行 grant
仍绑定原 subject 与原调用，不授予子实例新对象或新执行任何权限与资格。

创建以事务方式发布暂停子实例及持久 request/receipt。`fork-create` 以 `expected_preview_id` 和
`operation_id` 绑定完整请求，包括目标、新预算及指引原文。同 ID、同请求重复调用核对同一回执，
包括响应丢失后的核对；冲突请求或已有无关目标明确拒绝。回执核对不依赖父目录仍然存在。
目标父目录的私有 operation 记录持久保留已发布 child 的原身份和回执，即使 child 删除或移走，
同一操作也不重建它。中断的准备事务仅在该 operation 锁下按已登记的准确目录 inode 清理；
完整 stage 与原回执落盘后，恢复只发布同一个 stage。若发布尚未确认且原 stage 与目标均消失，
返回 `fork_publication_unknown` 并保留原身份/回执供核对，不新建实例。目标仍存在时继续核对
其回执与原件完整性。
须显式 `start --continue` 清除暂停后才在子实例自身门槛下推进；预览与创建均不启动模型或 solver。

可选方向指引按用户准确原文作为 advice 交给所选普通任务及合法后继；若选中正式审查，
通用分支指引延后到合法后继，保持审查中立输入。它不授科学 verdict、预算或执行权限。
网页从历史节点进入；打开暂停的新实例后点击“继续研究”才推进。错误时保留表单草稿；
同一 UI host/browser session 内可对已尝试的原操作
按同请求核对 receipt。跨 host 重启的通用 Web 操作恢复尚未建立；CLI/service 回执持久化。

适配器记录写者持有通用 `record-writer.lock` 共享 lease，未决调用检查使用独占非阻塞
lease。生命周期静止检查对现有记录目录内全部直接 `*.lock` 取独占非阻塞锁，作为旧记录的
保守兼容，不依赖领域前缀或已安装插件。写者顺序为 owner gate、record writer 共享锁、
node/admission、适配器私有锁；生命周期先取 owner gate 独占非阻塞锁，再取 node/admission
及直接记录锁，gate 互斥这两种顺序。活动写者阻止 fork/delete，未知原调用仍须先对账。

全部合作宿主进程必须看见同一稳定的 `/tmp/scidiscovery-owner-gates-<euid>` 目录及锁 inode，
并共享相同的实例挂载；进程存活期间不得删除或轮换 gate。PrivateTmp、容器等私有 `/tmp`
命名空间须由部署显式提供共同挂载；互不相见的私有 gate 不建立协调。改 TMPDIR 或 XDG
运行目录本身不能证明双方共享同一挂载。

只读原件视图与宿主统一协作 source lease 在配合协议的当前版本 writer 间保护引用边界，
仍是同用户软边界：同用户进程主动修改权限并原地写入原件 inode 可损坏其消费者；引用
元数据不是内容篡改检测器，实际选中科学消费仍须核对保存指纹。分支时不得混用升级前仍
活动的旧 writer：新 lease 不追溯 fence 旧进程。
这些控制不建立真实模型、solver 或科学资格。

## 明确实例删除

`instance_delete.py` 只删除明确指定的当前协议实例，请求绑定 goal ID、冻结 settings 引用和
操作 ID。未使用的已准备实例、暂停实例和已完成实例均须通过既有生命周期静止检查。
必要 accepted、submission、terminal、authority 与 retirement 控制仍须证明停写和身份；
不要求未选科学正文、旧代码草稿或已清导出仍存在。活动的 owner/source-reader 锁、未知执行
或交付效果、清理状态不明均阻止删除，不取消或重放工作。
canonical 路径和挂载子树检查限制清理范围；静止检查遍历的控制命名空间拒绝符号链接，
其他内部符号链接只解除链接，不遍历外部目标。清理可恢复准确固定目录的 owner 写权限，
绝不修改共享普通文件的权限。目标内的独立嵌套实例（包括仍可识别的损坏身份）阻止删除及清理重试。
prepare 与 fork 发布持有所在目录链的 gate；删除只获取一个按原目录 inode 绑定的物理
宿主 gate，跨 rename 同时保护原路径和待删除路径，避免清理期间在树内创建新实例。

实例外的私有持久操作记录固定目录 inode 和准确待删除路径。退役标记阻止普通效果入口，
包括未登记 owner 的实例。服务持有原宿主 gate 和本地 owner 锁，退役已登记的 anchor，
原子移动准确目录，再仅清理已记录的待删除目录。owner disposal 在这次有意移动前后仍校验
身份，普通 lease 不能关闭检查；外部 anchor 持久成为 deleted 后才发布完成回执。

完全相同的请求恢复原退役/清理事务并返回原回执，不接纳原路径下后来新建的实例。删除服务
不恢复已删证据，旧冷 checkpoint 不重新激活已删除 owner 代际。清理只删除本实例自有 Git、
临时代码导出与目录，不 chmod 或删除外部原件，不扫描邻实例求引用计数，不增加垃圾回收
权限。若 child 直接引用本次被删实例拥有的科学原件，对应科学消费可失效；已转移的 child
Git 和已复制控制仍由 child 持有。清理中断按同一 operation、原身份与回执续做，IO 期限
不重置科学预算。

## 受管 Skill 资产

`skill_supply.py` 将新实例绑定到实际 CLI 安装的唯一 `skills/` 树：源码发行与 `src/` 相邻，
薄安装与 `site/` 相邻，受支持的标准 wheel 布局使用 `sys.prefix/skills`。裸 wheel 不包含
这些外置资产；配置或 `SCID_SKILLS_ROOT` 不能覆盖来源。

Prepare 冻结展开后的命名集合与来源绑定，不冻结 bundle 字节。已有角色/Worker 的
`skill_set` 选择实际启用项。仅明确选中的执行插件可通过 `research_defaults.optional_skill_sets`
提供可选集合，安装或提供本身不启用。job 与 native intent 绑定准确集合、成员和配置修订；
既有执行和 fork 选择不引入插件后来的可选声明。修订只可改选已冻结集合，改变清单要求新实例。

`.agents/skills` 是可校验、可重建的发现投影；最终 native 挂载接缝将所选安装目录原地只读
bind。新实例不创建 Skill 对象、字节 manifest、副本或硬链接，安装与实例可以跨文件系统。
准备阶段只检查选中目录及手册元数据；资源仍为安装中的实时资产，绑定路径的更新会被后续
消费者读到。选中目录或手册缺失、链接时，诊断明确列出 Skill 名称、准确预期路径与修复方式。

Skill 绑定仅接受 schema v3 安装来源。旧 manifest/对象绑定在读取资产前拒绝，不提供
兼容读取、实例内冻结空钩子或迁移。当前 fork 保留安装来源与准确选择，不复制 Skill 字节。

此选择不屏蔽原生用户/系统/插件 Skill 来源，不改变已声明的原生权限；科学后端子进程不接收
Skill 挂载。标准 Codex 保留其冻结的原生 home 与认证；Cov 适配器不再提供专用原生启动器
或认证复制路径。
只读挂载仍属同用户软边界；具体配置见[配置参考](RESEARCH_CONFIGURATION.md)。

## 未发布准备快照的准确恢复

新派发在 prepare 和执行资源分配前检查已知的 review/breadth 准入，并在现有短锁内复核
已接受调用集合和准入条件。仅内置本地适配器自身的当前存活控制流，在尚未 submit 时遇拒绝或
取消，只清理本次临时准备目录，不登记外部 pending；清理失败仍属于本地清理问题。这不以崩溃后
缺少文件推断未启动，也不承诺取消已持久接受的调用。

准备可能产生外部效果的适配器，仍在填充未发布准备快照前保留准确宿主绑定。显式维护只可
补发布原准入后已完整持久写出的 accepted，或按原目录 inode 清理残缺快照；不重做 prepare、
准入或提交，不改原审批、reservation
与已消耗预算。清理后的未决绑定仍为 unknown，配置即使没有 execution authority，也不能借目录
消失重新准备；pending、后继 Worker 与 fork 继续保留这一阻断。

已发布历史绑定保留原字节和来源。历史可读不授予对新目录代际的现场维护权限。
无绑定临时目录只可通过既有维护命令的 `--unbound-local` 分支，明确选择 root、step 和准确
snapshot token。取得源实例、控制器及准确 records 写者锁后，要求该 step 所有保留 attempt 的
配置原件与 interface 投影完整一致，均证明内置本地执行且无 execution authority。缺原件、
混合历史、第三方准备、目标 token 已有绑定或任何 durable accepted 都拒绝清理。有限且不跟随
链接的删除只处理明确存在的残缺目标，不增加恢复记录、不改变执行状态、预算或重试权限。
目标不存在不证明曾成功清理；其他无绑定目录继续保留。准确命令与限制见 CLI 指南的准备快照维护部分。
