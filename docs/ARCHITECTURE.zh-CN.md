# 当前架构：薄 H/W/A/E 控制层

简体中文 | [English](ARCHITECTURE.md)

新实例由 `scid-research` 管理，实验工具为 `scid-experiment`。没有 LLM Root、MCP 调度服务或后台 Root daemon。
核心提供薄 CLI 与实例 UI；旧 CLI/MCP/UI、Root 宿主、平台配置生成与 legacy systemd 部署已退役。

`research_config.py` 是 TOML、CLI 与宿主入口共同的准备、默认值和校验路径。新实例冻结实际生效设置；修改新建声明不更新已有实例。`backends.py` 将 Codex 与显式 protocol 输运隔开，不接管科学判断、预算或执行授权。protocol 权限为 launcher 提示，不证明隔离；不支持原生续接和完整作者证明，不能取得正式独审。开启子 Agent 也不证明作者或用量完整。具体字段与限制见[配置与后端参考](RESEARCH_CONFIGURATION.md)。

`configuration_updates.py` 将运行配置修订与原始设置身份分开保存。新节点构建输入前绑定精确版本；已有节点及其原调用在校验、执行和恢复时沿用各自配置。保存只排队，不启动研究。配置变化保留累计预算与资源账本、未决执行事实和 FINAL 边界。可编辑字段及已生效、待生效状态见配置参考。

冻结的权限摘要分别记录请求值、实际策略、实施方式与限制；标准 Codex danger-full-access 不强制离线，read-only 不因网络请求启用联网，protocol/自定义 launcher 仅作权限提示，实际访问未知。

CLI 是应用核心，网页复用相同公共控制和读取逻辑。`control_operations.py` 持久记录 detached 推进及科学预算修订；独立控制进程使用原写锁，不依赖网页进程常驻。暂停阻止下一节点，已接受工作按原限制完成。预算修订在安全边界应用，不重置消费或未知用量；unknown 原调用须核对，不自动重发。

`user_guidance.py` 将全局/角色建议绑定到下一匹配新任务或后续研究。待应用项可按 revision 修改/撤销，已应用任务输入不可改写，后续研究撤销另留未来生效回执。建议可不采纳；显式目标变更保留原目标记录，并声明生效节点，不授执行权限或科学资格。

## 责任与数据流

```text
操作者的目标、输入、配置、有限预算
  -> CLI prepare：冻结实例设置
  -> controller：原实例写锁、预算、暂停、角色路由
  -> native：独立 H / W / A / E 原生线程
  -> 科学 JSON 与精确成果封存
  -> A 的科学去向 -> controller

W -> scid-experiment -> 冻结执行接口 -> local / 领域 adapter
                              -> 原调用 query / cancel / collect
CLI serve-ui -> 同一实例的只读视图与控制命令
CLI archive / checkpoint -> 原件核验与限定恢复
```

H 负责机制与假设；W 负责有界实验设计、实现与观察；A 负责贡献、证据缺口、后继方向和交付选择；E 负责所请求的证据工作。
控制层拥有身份、冻结绑定、预算、资格、权限和机械发布，不制造科学结论，也不在提示词中
给 Worker 增加哈希计算、比对、校验或哈希清单工作。Worker 写普通科学文件；控制程序
自动计算并核验精确绑定，在宿主私有空间保留机械记录。


本地结果指标仍须有不同的非空名称和明确有限数值。`unit`、`evaluation_key`、`direction`
与标签是可选科学说明，不强制优化方向枚举或科学文本长度。显式候选须绑定唯一已声明且保留
的精确成果；指标缺失或无法关联时保持 unknown，不改选其他指标或推断方向。坏指标、成果声明
或无法存入严格 JSON 的说明按字段或条目诊断，保留其他有效结果和有精确成果绑定的候选身份。`result.json`
原始字节不改写；紧凑预览与被省略字段的诊断链接该留存原件。

启用 H search 承诺时，`prepare --candidate-extra-slots N` 冻结 W 提名的额外名额，默认 2。
W 在既有科学返回的 `candidate_nominations` 中，对每个未 waived 的真实 H 机制声明一个代表
或明确缺口，包括 deferred 和 screened；另可提名至多 N 个不重复的额外备选。
每个代表须定位精确已登记候选并说明保留及机制归属理由；同模型覆盖多个机制须逐项解释。
当前调用的候选用 `{call_id, artifact}` 定位，历史候选沿用科学引用。控制只检查身份、
声明覆盖、重复和数量，不从调用绑定推断模型的机制，也不排序或判断科学真伪。
没有可用模型应明确缺口，不阻 partial 或 FINAL；只有 A 明确 waived 并给出科学否定或
不可行理由才免除机制覆盖，暂时相对低分应保留暂缓路线。

最近封存 W 的分类提名构成默认比较预览，独立分页保留完整提名、理由及原结论入口。
原候选池、实验和精确材料沿用完整分页及交付目录，池的数量不受提名名额限制。
A 可按需读取并用既有推荐与选择说明直接选择池内任一模型，不改写封存 W 提名，
也不需要为调入已有模型重新实验或登记。无 H search 承诺的任务不制造机制覆盖。

科学机制及处置列表没有固定四项或 128 个机制容量。已配置的初始调用机会、精确额外授权、
已接受调用消费、有限执行预算及未知原调用核对仍约束执行。分页索引保留全部机制和原科学文本，
默认导航视图继续有界。

`screened` 表示 A 已评价精确 W 证据，不排除以后继续深挖；`deferred` 暂缓并保留未决路线；
`waived` 才是 A 的明确科学排除。A 须针对原目标与约束，用证据支持每个排除的否定或不可行
理由；暂时相对落后或缺证据应说明暂缓，不能直接视为科学否定。H 先比较可信的竞争机制再
说明集中理由，单机制范围也由 H 解释；参数试验次数本身不证明不同机制均有判别证据。
控制不裁判理由的科学充分性。

机制索引提供已采纳 A 处置理由的有界预览，并链接完整科学 JSON 原件；原件不受导航页大小
上限省略。同状态重述或遗漏不替换原理由与来源；H 修订会清除当前处置，历史原件仍保留。
所有启用 search 的实例默认向 H/A 展示完整组合：实际已接受调用数、剩余初始/额外机会、
已完成独立 W→A 投入及未服务完整周期。调用数和周期数是活动事实，不是科学覆盖、价值排序
或每机制资源成本。稳定身份顺序只作导航；局部 improve/repair/validate 不抹去全局视野，
科学说明和 H 修订也不清零投入。所有未 waived 路线（包括 screened）进入未服务周期观察。
`search_policy.initial_calls` 配置初始受管调用机会；显式组合周期只控制提醒，不要求额外
portfolio_review 表单，不强制换路线，不阻止科学封存或 FINAL。A 在既有 scientific_result /
route_reason 中说明比较、集中、暂缓和排除依据，控制不判科学充分性。

广度预算判断读取普通工作可用量与运行时 `work/budget-status.json`。当前 protected FINAL
只按 provider 已报告消费计算 token 余额，未知账单保持未知，不估算收费或扣旧收口预留；
真实执行未知仍须按原调用核对。旧预算内收口实例保留原冻结预留。调用机会不预留实际资源，也不保证覆盖；昂贵调用应使用已有执行配置
和 W 阶段目标约束，不引入自动广度比例、最低机制数或新的执行权限。

H 只声明需要变更的 commitment；遗漏保留原承诺及已采纳 A 理由。repair 按稳定机制 ref
绑定唯一精确直接 W 观测，或通过既有 `implementation_selection` 选定的原 accepted 输入。
多个可能观测须精确选定；相同输出字节、label 或最近对象不提供来源身份。去重归档路径
不能证明逻辑输入身份，此类输出不能用于 repair 来源消歧。旧 W、call、accepted
及终态原件仍按自己的旧 H seal 校验，当前 H/A 的新授权另行冻结。进程已知成功不排除科学上
需要修复；unknown、原件缺失或改变、来源模糊及修复次数耗尽仍阻断，并在作者控制回执中提前
诊断。旧 screening 资格不继承，机会及总消费不退款。H 科学范围未变时，A 可用 `continue_w`
加显式局部 focus 请求审查后的下一有限 W stage；原 stage 消费继续累计。修订 H 用于科学承诺
改变，不能重置预算。

每个任务冻结其配置真正消费的辅助字段；未消费字段不进入原生回答的必填合同，额外科学内容
仍保留在封存原文。已启用的可选字段形状无法读取时局部诊断，不推断 progress 或作用域。
W 显式非空但形状损坏的 finding 作为 partial 交 A，不产生 screened 证据；缺失或合法但漏覆盖
的 finding 仍执行现有机制覆盖检查。真实 action、FINAL 路由、输入选择、独立资格和执行权限
继续显式校验。输入选择的 null 保留、`[]` 清空、有效列表替换；未解析列表不部分应用或静默继承。
已登记候选与其精确封存实现，可在 call/output/material 绑定一致时用同一可读引用选择；
相同字节而不同来源不合并身份，任意实现不自动成为候选。

新 job 将适配器可选的 `effect_scope` 声明冻结为公开 `configured_delivery`；声明须为
非空公开文本，不设固定长度上限。custom 未声明时范围为 `unknown`，不按启动器名称猜测。
内置目录适配器只复制并确认已留存的声明文件，不训练、不执行任务原生提交或科学审计；
此描述不授予权限或资格。W 须在临时材料消失前，将原任务实际需要的成果与原生回执保存到
既有声明输出。A 对照这些成果、真实适配器范围与任务要求说明缺口，仍可交付当前最佳的
部分成果，包括 FINAL；目标覆盖不会新增完成度硬门槛。

`exp` 是使用普通 `submit.json`/response 单槽的薄提交与等待工具。local 模式 W 的科学
视图由既有原生宿主在本次 native attempt 生命周期内处理提交并自动写回响应；external
模式仍由声明的 launcher 负责。两条路径均不引入额外 Agent、daemon、UDS 或 FIFO。

默认本地命令后端解析所选 Codex 安装的原生二进制，使用其 sandbox 和受限的科学子进程
文件视图。已接受的目录快照只读映回原科学路径，`artifacts/` 独立可写；单文件调用将
封存脚本映回其科学源码路径。后端只获得运行时文件、科学工作区及 task-native 权限配置，
不获得原生认证、provider 配置、控制原件或提交槽。原生 Worker 与后端遵守同一受支持的
legacy `workspace-write` 声明，包括网络权限和临时目录排除，并按各自工作目录、`TMPDIR`
和命名空间等义解释。原生 Worker 保留 `--sandbox workspace-write` 及捕获的 legacy
配置覆盖；只有后端 sandbox 使用表达同一声明的内部权限 profile。需要 Linux、
`bwrap` 及可解析的 Codex 原生二进制。named/default permissions、选定配置 profile、
managed policy、额外可写根以及无法忠实投影后端权限的自定义 launcher，会对受管启动
明确返回不支持，不为执行而替换其原生权限。内部权限 profile 不增加操作者配置项。
这些文件视图不构成防同用户恶意进程的隔离，也不对泛原生执行提供统一隔离保证。

受管执行输出、观察原件和历史保留共用实例既有的 `host-history/objects/<sha256>`。
宿主私有不可变 alias 可跨 call 共享 inode；相同字节不合并原 call、origin 或科学路径。
可变外部内容只独立冻结一次；已接受输入快照、Worker 输入及 collect/wake 视图通过硬链接
共享只读原件。需要编辑时把具体文件另存 `work/`，不预复制整棵输入树。共享要求同一文件系统，
不支持时明确失败，不回退全量复制。是否为受管不可变来源由生命周期证明，不按0400或链接数猜测；
0400 本身不构成防同用户主动 chmod 的写隔离。

协议 25 在最终原生启动处用 Linux 只读挂载保护共享输入，包括自定义 protocol argv。
准确注册的模块启动器保留宿主准备与提交服务，在最终科学进程命名空间施加同一保护；
其 provider/module 身份即使没有选定 Skill 也冻结，普通包装脚本不能据名字豁免。
先建立 workspace/work 挂载点，再覆盖输入、Skill 和动态结果目录；普通工作文件和输出仍可写。
Cov 与受管子进程在路径重映射完成后追加保护，只保留准确 accepted 输出目录的可写例外。
宿主发布核对已绑定动态目录的身份，目录被替换时拒绝发布。缺少实际挂载能力便在启动前拒绝，
不裸启动或复制整树回退。原生网络、web、subagent 和 sandbox 声明保持；别名核对只扫描准确
workspace 与框架已知路径的元数据。同用户外部宿主进程、既有文件描述符和外部别名仍是软边界。

`storage_policy` 随实例及准确 job/call 配置冻结，默认 `enabled=false` 且各额度为 null。
启用须至少明确一项正整数 `max_scan_entries`、`max_files`、`max_file_bytes`、
`max_total_bytes` 或 `max_instance_bytes`，不暗中启用旧常量。
实例累计额度串行核对合作保留/物化写者，按唯一 inode 的完整 regular 文件大小计量，
含正在写入的 partial；reflink 保守计完整大小，hardlink alias 不重复计费。
这不是任意原生 Worker 写入的 OS 磁盘配额。关闭时不进行实例全树用量扫描；
有限执行/IO deadline、显式 handoff 额度及独立执行授权资源合同继续有效。
已派发身份、终态和退休事实等必要控制回执不因内容额度耗尽而拒写，防止丢失恢复依据；
回执字节仍进入后续用量扫描。派发前 acceptance、内容原件、日志及物化继续受额度约束。

已验证、同实例既有不可变 inode 的硬链接不新增 regular 文件字节，因此不重复扫描实例用量，
即使既有用量已超额也可建立这种引用；独立冻结、新投影及日志新增字节仍须通过准入。
用量扫描只容忍过程中消失的条目或后代目录，实例根缺失及其他访问错误仍失败。
显式开启实例字节额度时，增长中的进程日志仍会触发用量扫描，不跨解锁区间缓存旧用量。

本地科学日志按原有顺序流式替换路径，完整保留跨块匹配与原文。两条日志的输入核验、转换和
发布共用同一有限操作期限；首次流式计算输出身份不写文件，仅当 CAS 缺失时第二遍流式写入
一个原子发布 inode，已有内容不再次完整写出。内存取决于有界块与替换元数据，不随日志总长度
增长；原始日志不改写、不截断。

控制侧保留完整绑定索引、回执和逐文件省略绑定；默认科学视图提供人可读引用、观察与限制。
新视图明确标注为投影，源代码、用户原件和科学正文保留原内容。独立操作侧导出工具
`scripts/acceptance/worker_evidence_view.py` 核验显式绑定的原索引及已索引字节，生成分开的
`control/` 与 `science/` 目录。Worker 只获得 `science/`，输出父目录及 `control/` 留在控制侧。

`science/index.json` 默认给出简短省略摘要，包含 `details_ref` 和 `when_to_open`。
当某个候选或实验的材料覆盖会影响判断时，可按引用读取有界分页中的人可读材料名、类别、
范围与原因；详情不作为普通证据的整份清单。详情是可用性信息，不等于被省略原件；未提供
原件或安全读取路径时标注 `not_available_in_this_view`。缺失材料如何影响科学判断由 Worker 决定。

默认省略元数据整体不超过编码后 JSON 的 8 KiB；多份清单通过 `omissions_next` 继续读取。
详情页最多 12 项且最终 JSON 字节不超过 16 KiB，导航与文本转义均计入。长科学字符串仍为
字符串预览，并列提供 `*_truncated` 与 `*_details_ref`；按链接依次拼接 `{text, next}` 页中
解码后的 `text` 可精确还原全文，末页不含 `next`。短字符串保留原形状。这些限制只针对
省略部分，不针对整个证据索引；文本详情入口也不等于被省略原件的读取入口。

## 实现归属

| 责任 | 唯一实现范围 |
| --- | --- |
| 实例准备、路由与暂停 | `research_loop/controller.py`、`runtime.py`、`instance_control.py` |
| 统一配置与后端 | `research_config.py`、`backends.py` |
| 后台操作与用户方向 | `control_operations.py`、`user_guidance.py` |
| 原生执行、原线程续接与计量 | `native.py`、`execution.py`、`continuation.py` |
| 科学合同、原文与成果 | `contracts.py`、`semantic.py`、`instance_science.py` |
| 候选比较与交付 | `selection.py`、`delivery.py`、`worker_delivery.py` |
| 执行注册与原调用恢复 | `experiments.py`、`managed_wait.py`、`local_experiments.py`；领域插件提供 adapter |

| 实例 UI | `instance_ui.py`、`instance_render.py`；不建立第二份状态 |

实现升级采用新前缀，在停止或核对旧 writer 后显式切换 wrapper，并保留旧前缀供回退。
科学原件继续保留，但不承诺旧协议实例的执行兼容；历史源码指纹仅作元数据，不作准入条件。
任务、输入、成果原件、声明权限、有限预算及外部调用身份仍须精确绑定，升级不授权重放未知调用。
稳定角色与证据规则只传一份：Codex standard/options launcher 使用 developer，protocol 与继承配置的自定义 launcher 使用 prompt。
任务包保留科学问题、精确输入与响应字段；正式独审使用专属独立审查规则。准入只在一次只读计算内复用事实，
正式 writer 边界与后续准入重新读取配置、账本和用量。已报告 input+output 是观察下界，计量未知不等于零消费。
普通已接受节点可完成超过软目标的工作，共享额度在下一边界检查；原外部调用、FINAL 与作者收尾的有限 deadline 保留。
非执行插件 registry、Operation 编译宿主、Artifact 存储宿主、helper 与 finalizer 已退役。
保留执行叶 schema、来源规则、有界进程 IO 和真实 wire transport；沿用其窄模块路径减少纯搬移，
不再提供 catalog 或科学调度。曲线和图证据算法为自包含 Skill 脚本；执行扩展见[接口参考](PLUGIN_RUNTIME_API.md)。

## 不可退化的边界

- 科学作者负责比较和选择候选。控制按首次观察顺序保留全部候选，包括同分和缺少指标者。
  紧凑预览只作机械省略并链接完整原件，不裁剪交付目录。选择策略版本 2 精确为
  `{"version":2}`，目录不启动领域调用。A 交付须明确命名目录成员，在 `scientific_result`
  说明选择依据。`candidate_comparison` 是可选科学说明，其行、`keep`、理由和证据步骤格式
  不授予或阻挡交付；真实 audit/deliver 仍要求精确可用候选、资格与执行权限。
  null 不授权交付。协议 25 拒绝旧冻结协议，不迁移或改写其原件。
- 一个实例只有一个推进写者；只读页面不调模型，不重建第二份预算或科研状态。
- 科学原文、成果、配置和原调用均按精确身份冻结；修订不能继承旧对象的批准或资格。
- 来源未知保持 unknown；正式独审排除精确对象的全部已知作者与参与者，普通 A 不自动成为正式审查。
- 科学判断、正式资格与执行批准分别解释；聊天或手写决定文件不构成人工批准。
- 未知外部提交只核对原调用，不退款、不重发；恢复不重置额度、不生成另一个 owner。
- UI 转义作者内容；附件按精确封存成员读取，HTML/SVG 仍下载，不执行。
- 当前信任 Worker 及宿主同权限进程，属于软控制边界，不主张防恶意进程隔离。

授权读取只核对不可变声明、身份、精确对象、范围及已声明的期限或撤销状态，不遍历执行结果或重放科学结论。
真实效果入口显式检查科学资格与原件完整性，并独立检查当前预算、暂停、活动或未知执行的准入条件。
结果损坏或缺失不抹去已接受意图和消费，也不妨碍查看或撤销授权；它会阻止新效果，或使相关终态和计量事实保持未核实。
已接受调用的 collect/cancel 保留原权限与调用身份，不变成新的提交授权，也不重发原调用，仍受原调用或显式有限维护窗口约束。

普通 A 任务要求逐项对照原目标和授权范围，以可定位观察及实验条件支撑关键主张，区分
测量、推断和假设、目标指标与代理及敏感性检查。A 按同一目标准则比较相关候选，说明
冲突证据、不确定性和缺失输入。流程结束、审计资格、预算耗尽、`finish` 和交付均不证明
未测量的目标已经完成；停止时 A 须报告未满足的目标。

A 明确给出 `candidate_recommendation` 时（包括 FINAL），须填写
`selection_explanation`：当前 `criteria` 与 `criteria_change.status`
（`unchanged` 或 `revised`）。修订时须声明 `prior_criteria`、`changes`、
解释原因且可定位的 `evidence` 和 `accepted_tradeoffs`；未修订时这些详情为 null。
A 须对照先前 H/W 设计及报告中的比较条件、门槛与回退规则；放宽这些规则即为修订，
即使当前报告已经采用新规则，也不能因此称为未变。
首次选择可如实说明没有前序准则；规划阶段没有候选推荐时可用 null。
框架只检查声明完整性，不判断科学真伪、充分性或候选排序。缺失说明在封存前通过冻结的
output-repair 策略退回同一 A 补填。FINAL 补填保留同一任务、session、最终返回授权、
累计消耗、有限次数及原单次时长；共享余额耗尽不撤销该次完成或其原授权交付。
它不授权新实验、新科学节点或重试未知执行。

标准单命令 `codex` 的 CLI prepare 默认冻结最多两次仅输出补填或原受管执行唤醒，在私有策略中绑定原
native home，保留配置、认证及权限来源；冻结绝对 launcher 调用路径和目标文件，
不替换符号链接调用语义。未提供节点策略时，各角色软目标引用原全局上限，不预扣额度。
显式策略优先且可关闭默认补填；自定义 launcher 和直接 controller API 调用仍须显式策略。
默认通过 `execution_wake: true` 为 `output_only` 冻结一个窄例外：
W 在原受管调用 pending/running 时正常交回科学 JSON，宿主保留未封存等待 checkpoint，
不启动新的 native turn 来轮询。只有这些精确原调用的已核验终态可唤醒同一 W session，
解释原结果并完成返回；宿主拒绝该窄唤醒中新建受管调用，即使使用旧配置客户端。
同用户原生 shell 仍是软边界。该例外共用原有限 attempt、累计预算、权限及 home/session，
不授权失败任务重试、科学工作修复或 fragment。
旧冻结 output-only 策略缺该标志不追认；旧显式完整 resume 策略保留已有唤醒行为，除非明确关闭。
W 合同说明冻结的唤醒权限及 pending 时正常交回方式，但不强迫活 W 交回，也不证明 session 可用。
缺权限在宿主等待终态前明确诊断，原 checkpoint 和调用仍保留。
执行器回执给出宿主生成的紧凑 `handoff.action`，与宿主等待共用一个纯判定规则：
`return_control`、`poll_original`、`consume_terminal`、`reconcile_or_stop`。
消费终态必须核验精确原件，不能只凭状态字符串。`poll_original` 要求在同一 native turn
按 1 秒间隔持续等待和查询同一原调用，只要仍 pending 且可查，就持续到交接指示改变或
实际原预算、时间或宿主停止限制触发，不设查询次数上限。终态字符串须先对同一调用
reconcile 再消费；unknown 或不可用事实须核对或明确报告障碍，不能盲轮询。
这是交接合同，不强制任意模型交回，也不增加执行权限。新任务冻结这段交接说明，旧任务和调用原件不改。

普通 A 明确 `finish` 即结束本轮且零提交；明确 `deliver` 只消费原封存 A 的精确候选授权，不强制新 FINAL A。启用选择策略时，普通 A 原任务先冻结并展示完整比较目录，交付仍核对同一目录、原件及资格；失败或缺资格保留未决结果，不自动改选或新起科学作者。预算阻断保留原路线；角色份额按账本有效总 token 授权计算，显式增额后恢复仍重新核对份额与原执行。局部 W 只提名本次冻结范围内机制；按机制的最近声明及各自来源供 A/FINAL 读取，其他机制既有代表和缺口保持，新机制显示 pending，screen 仍可全局。

新 `prepare` 冻结 `final_a_completion_policy` version 1。普通状态检查剩余共享额度能否启动下一动作；该模式不为 protected FINAL 预扣共享 token、时间或步数，也不在启动时预付整个节点 token 目标。已报告 token 余额为正即通过普通 token 启动检查，仍须满足原有限时间、步数、完整性与执行门槛。H/W/A/E 单节点 token 目标统一为 soft，达线提示收口，不仅因达线拒绝新受管实验或强制转 A，原节点可以完成原结果；author closeout 的 token permit 同样为软目标，有限时间仍强制执行。协议 25 仅接受 soft 节点设置；旧协议只读，不静默改写冻结 hard 设置。不能启动便在现有控制账本进入持久 FINAL。每个 FINAL 周期通过 `final_a_return` 只接受一个精确原始 A，基于已有已接受 W 给结论、明确选择，并说明未满足目标与缺失输入。共享 token、总时间或步数预算不足、为零或超额均不否决这次 A；有原件与交付权限时由 host 执行其原授权提交和同操作确认，输出真实结果。缺少 W、原件、权限或未核对原执行时明确未提交，不制造科学结果。未配置可选节点预算时，原冻结全局 token/时间设置提供最终调用的参考目标与有限单次时长。

provider 已报告实际用量、cached input、时间及步数全部保留；未知账单继续标注未知，不估算扣费，原上限不改、不退款；`final_overrun` 单列 token 超额。同一 FINAL 周期不派发新的 W/E、独立科学审查、纠正节点或另一轮 A，原 host 提交内必要机械资格检查仍保留。
冻结的 output-repair 策略仅可续接同一最终 A 任务补全输出，保留原授权、累计用量、
有限次数及原调用时长；它不授权重试未知执行。

这次精确最终 A 的原生完成与账单覆盖分别判断。原 `turn.completed` 事件、退出码 0、
原进程组已确认清理及科学输出完整时，即使用量缺失或无法与实时计数对齐，仍可封存。
已观测下界和未知账单分别保留，不补造零用量或完整计费覆盖。仅计费未知也不阻挡该 A
明确授权的原 submit 和同操作 confirm；缺少完成事件、非零退出、清理未知或外部效果
未核对仍保持原未决边界，不授权替代 A 或重放。

用户之后明确提高阈值且足以启动原待执行 normal 动作时，下一次 run 从 FINAL 前保存的逻辑路由恢复。`budget-amend` 本身只记账，不启动模型。恢复使用单调递增的新物理编号，所有旧最终 A、交付与消费不变；运行中的原最终 A 先收集，未知外部效果须按原调用核对。最新修订降低阈值或提高后仍不足，不恢复、不重复 A；以后再次预算不足进入新周期，各周期一个最终 A。主动 closeout 没有待恢复路由时保持终态。缺少冻结策略的历史实例保留原行为。

后续只可使用原决策的有限 `submit` 和同操作 `confirm`。即使共享总时间已经超出，
原 A 单次调用、清理和每次交付动作仍保留已配置的有限时间上限。
资格、授权、精确原件核对、RSS 和取消仍有效。未知外部提交只核对原调用，绝不重新提交。
原生执行没有逐 request 准入 hook；此策略不保证进程、清理或传输故障后仍能产出报告或提交成功。

## 声明来源与审查

资格消费精确冻结原件，不按名字、相同字节或最近对象猜测来源。受管执行可通过
冻结能力声明输入来源；自包含 TCAD V2 package 必须匹配准备归档和原 reviewed
producer，编译 V3 输入保持原 compiler 链。明确不完整的声明不能回退为更广的来源主张。
可选 observer 须另行启用冻结来源合同，并提供绑定精确 observation 的来源视图；
展示 coverage 本身不授予资格。真实 producer 贡献即使未被选为 implementation 也进入
作者集合；普通 parent 链不自动生成作者关系。

普通探索不要求固定的正式审查阶段。所请求的审查须绑定精确对象与经核验的贡献者；
普通 A 解释不构成独立审查。来源限制沿冻结输入传播，未知来源保持 unknown。
这些核验仅覆盖框架声明范围，不证明任意 native 外读封闭或科学正确。

## 历史任务分支

`fork_service.py` 为 CLI 与 UI 提供共同的预览和创建路径。父实例须冻结协议 25、已完成且静止，
并保留所选精确逻辑任务 N 及其声明依赖的原件。不支持的协议、缺失历史 cut、歧义身份或缺失
原件均明确拒绝。未知 native、受管执行或交付效果须先按原调用对账；分支不自动重提这些调用。

新分支拥有新实例身份，首任务保留逻辑编号 N，在新 native session 中从 N 的冻结首次科学输入
重跑。N 的输出、后续任务、工具反馈及 continuation/repair attempt 上下文不作为该任务输入继承。
入口只选逻辑任务，不提供任意 attempt 断点或 remaining-at-cut 预算模式。普通任务保留所选路由；
FINAL 与 closeout 任务保留阶段和来源 cutoff，新预算本身不把它们改为普通探索。正式审查保留
中立的精确 subject 合同与独立性门槛；工程修复保留有界 repair 合同。有 continuation 或输出修复
的任务也从首次输入重跑，不续接这些 attempt。

`fork_sources.py` 复用通用目录 inventory，通过已验证硬链接完整保留静止源目录的私有快照。
它是当前目录的保留超集，不伪称任务 N 时刻已有完整历史目录快照；科学可见范围另由所选 job
和准确原输入 cut 限定。`visibility=private_snapshot` 条目不进入普通节点视图，内部精确摘要
引用仍可解析，但不因此成为科学输入或资格。fork/cache 实现存储排除，已有原件 object 存储
仍完整保留；目录清单不遍历领域 JSON 或依赖领域文件名。`originals.py` 按原身份与摘要解析来源。已封存为 0400 的原件直接共享；仍可写或权限不同的
原件先在父实例私有 `host-history/fork-cache` 中封存一次，再共享。原文件内容和权限
不变。public 视图只链接明确选定的已留存公开原件，不暴露私有控制元数据。嵌套分支共享这些
不可变 inode，同时保留各自的原身份与本地路径。
已明确绑定在实例内的主机密钥按已验证的私有来源定位排除；未知文件仅凭名称像凭证，
不获得排除许可，无法识别的存储归属仍标为 inventory gap 并阻止 fork。

每个留存目录项都是持有引用，文件系统链接数是引用状态的权威，不另建可变引用计数数据库。
删除父或兄弟实例仅移除其引用，子实例仍可使用原件；父实例的快照缓存随父实例存储保留，
最后一个链接删除后才释放数据。全部共享源与目标必须位于同一文件系统；不支持链接时明确
拒绝，不回退全量复制。需要新建快照的父实例必须允许私有存储写入。已有复制式 manifest
仍可读取。后续任务执行通过节点本地硬链接共享冻结输入；可变原件首次冻结和显式编辑副本仍需独立写入。纯读取校验允许硬链接引起的元数据变化：0400 普通文件仅 ctime 改变，且路径、
inode、权限、大小及 mtime 保持不变时，每层读取器最多尝试三次。每次必须得到稳定的文件
代际并符合准确原件绑定，中断的摘要不入缓存；持续变化则拒绝。这不会重试创建、控制动作
或外部执行。native home、认证、模型 session、工具、solver、许可证及执行环境不复制。
冻结的模型、权限和 launcher 声明仍只是声明；任意未冻结 native 外读不保证可移植。声明的外部
runtime/adapter 读取范围、命名空间映射和交付目标保持冻结；分支不复制、重建或扩大它们，
子实例继续时仍须合法可用。当前闭包
上限为 65,536 项、4 GiB、16 层祖先，每份需解析的控制 JSON 上限为 32 MiB。

操作者须声明正的有限新 token、活动时间及控制动作上限。子实例记账衡量新工作，逻辑编号 N
不等于新消费 N 次动作；继承的科学投入与比较机会仍进入科学历史。历史成本单列：计量不完整
则保持 unknown 并保留已知下界，历史活动时间及全部控制动作不伪称精确重建。新额度不清零
历史科学投入，也不把缺失用量变成零。来源限制随精确原件传播；历史审查 verdict 和执行 grant
仍绑定原 subject 与原调用，不授予子实例新对象或新执行任何权限与资格。

创建以事务方式发布暂停子实例及持久 request/receipt。`fork-create` 以 `expected_preview_id` 和
`operation_id` 绑定完整请求，包括目标、新预算及指引原文。同 ID、同请求重复调用核对同一回执，
包括响应丢失后的核对；冲突请求或已有无关目标明确拒绝。回执核对不依赖父目录仍然存在。
目标父目录的私有 operation 记录持久保留已发布 child 的原身份和回执，即使 child 删除或移走，
同一操作也不重建它。中断的准备事务仅在该 operation 锁下按已登记的准确目录 inode 清理；
完整 stage 与原回执落盘后，恢复只发布同一个 stage。若发布尚未确认且原 stage 与目标均消失，
返回 `fork_publication_unknown` 并保留原身份/回执供核对，不新建实例。目标仍存在时继续核对
其回执与原件完整性。
须显式 `start --continue` 清除暂停后才在子实例自身门槛下推进；预览与创建均不启动模型或 solver。

可选方向指引按用户准确原文作为 advice 交给所选普通任务及合法后继；若选中正式审查，
通用分支指引延后到合法后继，保持审查中立输入。它不授科学 verdict、预算或执行权限。
网页从历史节点进入；打开暂停的新实例后点击“继续研究”才推进。错误时保留表单草稿；
同一 UI host/browser session 内可对已尝试的原操作
按同请求核对 receipt。跨 host 重启的通用 Web 操作恢复尚未建立；CLI/service 回执持久化。

适配器记录写者持有通用 `record-writer.lock` 共享 lease，pending inventory 使用独占非阻塞
lease。生命周期静止检查对现有记录目录内全部直接 `*.lock` 取独占非阻塞锁，作为旧记录的
保守兼容，不依赖领域前缀或已安装插件。写者顺序为 owner gate、record writer 共享锁、
node/admission、适配器私有锁；生命周期先取 owner gate 独占非阻塞锁，再取 node/admission
及直接记录锁，gate 互斥这两种顺序；普通归档导出同样持有独占 source gate。
活动写者阻止 fork/archive/delete，未知原调用仍须先对账。

全部合作宿主进程必须看见同一稳定的 `/tmp/scidiscovery-owner-gates-<euid>` 目录及锁 inode，
并共享相同的实例挂载；进程存活期间不得删除或轮换 gate。PrivateTmp、容器等私有 `/tmp`
命名空间须由部署显式提供共同挂载；互不相见的私有 gate 不建立协调。改 TMPDIR 或 XDG
运行目录本身不能证明双方共享同一挂载。

只读原件与宿主统一协作 source lease 在配合协议的当前版本 writer 间保护共享边界，仍是
同用户软边界：同用户进程主动修改权限并原地写入共享 inode 可损坏所有引用，摘要校验负责
发现损坏。分支时不得混用升级前仍活动的旧 writer：新 lease 不追溯 fence 旧进程。
这些控制不建立真实模型、solver 或科学资格。

## 明确实例删除

`instance_delete.py` 只删除明确指定的当前协议实例，请求绑定 goal ID、冻结 settings 摘要和
操作 ID。未使用的已准备实例、暂停实例和已完成实例均须通过现有归档静止检查。活动的
owner/source-reader 锁、未知执行或交付效果、清理状态不明均阻止删除，不取消或重放工作。
canonical 路径和挂载子树检查限制清理范围；静止检查遍历的控制命名空间拒绝符号链接，
其他内部符号链接只解除链接，不遍历外部目标。清理可恢复准确固定目录的 owner 写权限，
绝不修改共享普通文件的权限。目标内的独立嵌套实例（包括仍可识别的损坏身份）阻止删除及清理重试。
prepare、fork 发布与冷恢复持有所在目录链的 gate；删除同时锁定原路径和待删除路径，
避免清理期间在其中创建新实例。

实例外的私有持久操作记录固定目录 inode 和准确待删除路径。退役标记阻止普通效果入口，
包括未登记 owner 的实例。服务持有原宿主 gate 和本地 owner 锁，退役已登记的 anchor，
原子移动准确目录，再仅清理已记录的待删除目录。owner disposal 在这次有意移动前后仍校验
身份，普通 lease 不能关闭检查；外部 anchor 持久成为 deleted 后才发布完成回执。

完全相同的请求恢复原退役/清理事务并返回原回执，不接纳原路径下后来新建的实例。删除服务
不恢复已删证据，旧冷 checkpoint 不重新激活已删除 owner 代际。共享文件通过普通 inode
引用留存，删除一个实例不移除其他分支原件，不引入手工引用计数数据库或新垃圾回收权限。

## 扩展规则

领域算法、科学 schema 和执行 adapter 归插件。核心按冻结的声明能力路由，不按领域
或插件名称分支决定科学行为。schema 结构、声明的科学语义与 validator 必须一致；
工程故障不能伪装成科学拒绝或科学重试理由。恢复保留原限制和失败证据。
只读视图与 UI 呈现同一封存科学字节，不改写科学内容。
CLI result/materials/artifact 与网页通过同一精确原件 API 读取，下载不覆盖已有目标；网页配置、实例选择、预算排队与用户方向复用公共接口，只打开明确选择的实例。

## 受管 Skill 资产

`skill_supply.py` 在私有共享库首次独立冻结显式资产，之后为各实例建立自有硬链接，
把角色/Worker 选择绑定到任务与 native intent。`SCID_SHARED_STORE` 可指定精确库路径，
默认使用宿主用户缓存；库与实例须支持同文件系统硬链接，不逐实例退回复制。
库的共同写锁覆盖不同集合的同内容首次发布，不维护另一份引用计数账。
删除安装来源、库目录或兄弟实例不影响本实例已持有的原件引用。
`.agents/skills` 是已验证、可重建的发现投影。来源更新不刷新冻结字节，
修订只能改选已冻结集合，新 ID/版本要求新实例。归档、fork 和冷恢复保留普通对象，
在接收根重建投影，不依赖安装来源或父实例继续存在。原生用户/系统/插件 Skill 继续继承，
原生权限 profile 保持原语义；具体配置见[配置参考](RESEARCH_CONFIGURATION.md)。
